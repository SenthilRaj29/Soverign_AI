1. THE BIG PICTURE (WHAT THIS PROJECT DOES IN SIMPLE WORDS)
--------------------------------------------------------------------------------
Imagine a large industrial company (like a power plant, chemical refinery, healthcare 
facility, or defense facility). They have sensitive manual books, maintenance records, 
inspection photos, and sensor datasets.

They CANNOT send this data to public cloud AI systems (like ChatGPT or Claude) because:
- Cloud AI sends confidential files outside the factory network.
- It risks intellectual property theft, data leaks, and compliance violations.

OUR SOLUTION:
We built a "Sovereign AI Workbench"—a super-smart AI assistant that runs 100% 
LOCAL on the company's own computer/server with ZERO internet connection (Air-Gapped). 
It reads manuals, analyzes sensor spreadsheets, inspects physical damage photos, 
applies safety policies, creates official PDF/Word reports, and logs everything for security.

2. THE 10 MAIN PARTS OF OUR SYSTEM & WHAT THEY DO
--------------------------------------------------------------------------------

[PART 1: OLLAMA + GEMMA 3 (The Local Brain)]
- What it is: A powerful open-weight Large Language Model running directly on local hardware.
- What it does: Performs reasoning, planning, decision support, and summary generation. 
  It processes prompts and responds without sending a single byte to the internet.

[PART 2: DOCUMENT INGESTION SERVICE (The Reader)]
- What it is: A multi-format document reader (`backend/app/services/ingestion.py`).
- What it does: Takes PDFs, DOCX Word files, TXT manuals, and CSV/XLSX spreadsheets, 
  and splits them into small readable paragraphs ("chunks").

[PART 3: PADDLE OCR SERVICE (The Scanner)]
- What it is: Local optical character recognition engine (`backend/app/ocr/ocr_service.py`).
- What it does: Converts scanned paper documents, printed manual images, and PDF pages 
  into clean text so the AI can read scanned paper records.

[PART 4: SENTENCETRANSFORMERS + QDRANT VECTOR STORE (The Smart Memory / RAG)]
- What it is: A vector search database (`backend/app/rag/vector_store.py`).
- What it does: Converts document chunks into mathematical numbers ("embeddings"). 
  When a user asks a question, Qdrant instantly retrieves the exact matching safety manual 
  section. It also enforces Role-Based Access Control (RBAC)—so regular workers cannot access 
  top-secret executive files.

[PART 5: PYTHON DATA ANALYZER (The Spreadsheet Expert)]
- What it is: A local code sandbox using Pandas (`backend/app/services/data_analyzer.py`).
- What it does: Reads industrial sensor spreadsheets (`pump_sensor_data.csv`), calculates 
  averages, peak values, and detects abnormal spikes (like pump temperature exceeding 85°C).

[PART 6: MULTIMODAL VISION SERVICE (The Visual Inspector)]
- What it is: Image analysis tool (`backend/app/services/vision_service.py`).
- What it does: Inspects equipment photographs to spot surface cracks, rust, casing 
  damage, or physical wear on heavy machinery.

[PART 7: OPENWORKER AGENT ORCHESTRATOR (The Manager)]
- What it is: The central coordinator (`backend/app/agents/orchestrator.py`).
- What it does: When a user gives a high-level goal, the Orchestrator breaks it down 
  into sub-tasks, chooses which tool to call (Data Analyzer ➔ Vision ➔ RAG ➔ Reports), 
  and stitches everything into a unified conclusion.

[PART 8: REPORT GENERATOR (The Document Creator)]
- What it is: Automated document formatter (`backend/app/reports/report_generator.py`).
- What it does: Takes the agent's findings and generates official ready-to-sign `.docx` 
  and `.pdf` maintenance approval reports on local disk.

[PART 9: SHA-256 AUDIT TRAIL SERVICE (The Security Guard)]
- What it is: An immutable compliance logger (`backend/app/audit/audit_service.py`).
- What it does: Every time the AI takes an action or generates a report, it calculates 
  a cryptographic SHA-256 digital signature and logs it into a tamper-proof audit file.

[PART 10: REACT + TAILWIND FRONTEND (The Control Room)]
- What it is: A modern dark-mode user dashboard (`frontend/src/App.tsx`).
- What it does: Allows human engineers to type goals, see live execution steps with 
  millisecond timers, download generated reports, and view sovereignty telemetry (0 network egress).

3. STEP-BY-STEP WORKING WORKFLOW (REAL EXAMPLE)
--------------------------------------------------------------------------------

Let me walk you through a real-world scenario from start to finish:

SCENARIO:
Lead Safety Engineer Senthil uploads a sensor CSV file and an inspection photo of 
Centrifugal Pump CP-9000, and types:
"Analyze pump sensor data and inspection photo, check safety SOPs, and prepare an approval note."

HERE IS EXACTLY WHAT HAPPENS INSIDE OUR PROJECT:

STEP 1: USER SUBMITS REQUEST ON THE FRONTEND
- The user clicks "Start Sovereign Agent Workflow" on the React dashboard (`http://localhost:5174`).
- The frontend sends a JSON request to the FastAPI backend endpoint `/api/tasks/execute`.

STEP 2: AGENT ORCHESTRATOR CREATES A PLAN
- The `OpenWorkerAgentOrchestrator` receives the request.
- It asks the Planner to create a step-by-step execution roadmap:
  Step A: Analyze sensor CSV.
  Step B: Inspect visual image.
  Step C: Search knowledge base for safety rules.
  Step D: Generate reports & record audit log.

STEP 3: SENSOR DATA ANALYSIS (Python Data Analyzer)
- The agent passes `pump_sensor_data.csv` to `PythonDataAnalyzer`.
- Pandas reads 1,000 telemetry rows, calculates rolling averages, and detects that 
  temperature reached 91.7°C (which violates the standard 85.0°C limit 3 times).

STEP 4: VISUAL INSPECTION (Multimodal Vision Service)
- The agent passes `pump_damage.jpg` to `MultimodalVisionService`.
- The local vision model detects surface oxidation, rust, and a hairline crack on the casing.

STEP 5: SAFETY POLICY SEARCH (RAG + Qdrant Vector Search)
- The agent queries Qdrant Vector Store for keywords: "pump temperature shutdown limit LOTO".
- Qdrant retrieves Section 2 of `NOVA_Safety_SOP_LOTO.txt`, which mandates:
  "Immediate emergency shutdown is REQUIRED if pump operating temperature exceeds 85°C."

STEP 6: SYNTHESIS & RECOMMENDATIONS
- The agent combines all three sources:
  1. Sensor Data = Overheating (91.7°C).
  2. Inspection Photo = Physical crack on housing.
  3. Safety SOP = Mandates immediate shutdown above 85°C.
- Recommendation: "EMERGENCY SHUTDOWN REQUIRED immediately. Isolate power per LOTO procedure."

STEP 7: AUTOMATED REPORT GENERATION
- `ReportGenerator` creates two official files:
  - `task_b478e969_maintenance_report.docx`
  - `task_b478e969_maintenance_report.pdf`
- Both documents contain the summary, findings, recommendations, and source citations.

STEP 8: CRYPTOGRAPHIC AUDIT LOGGING
- `AuditService` hashes the entire task trace using SHA-256 and writes an audit log 
  entry to ensure full accountability for compliance audits.

STEP 9: FRONTEND DISPLAY
- The React dashboard receives the response and displays:
  - Executive Summary & Findings cards
  - Highlighting red Emergency Action box
  - Download buttons for DOCX/PDF reports
  - Live execution trace timeline showing millisecond timing per step.

4. CHEAT SHEET FOR SIH PRESENTATION (WHY WE CHOSE THIS TECH)
--------------------------------------------------------------------------------
- Why Gemma 3 / Ollama? -> Open-weight, runs locally on GPU/CPU, zero cloud data leak.
- Why Qdrant? -> High-performance vector search supporting payload RBAC metadata filters.
- Why PaddleOCR? -> Lightweight local OCR that runs on CPU without cloud services.
- Why Pandas in Docker? -> Safe, isolated calculation engine for industrial spreadsheets.
- Why SHA-256 Audit Logs? -> Provides legal proof that AI outputs are traceable and non-tampered.
- Why FastAPI + React? -> High-speed async backend + enterprise-grade interactive control UI.
